Server boundary

Adapters isolate source secrets.

  • Provider registry is hard-coded in backend; no provider selector env value exists.
  • Each adapter owns source-specific server credentials and root configuration.
  • Dropbox SDK exchanges refresh token for short-lived access tokens.
  • Shared pipeline never receives credentials; logs/API errors never expose them.
Reconciliation rules

Only changed work reaches models.

  • New file → download, process, describe/embed, store.
  • Newer modification time → re-ingest.
  • Unchanged file → no model request.
  • Missing source file → delete linked Qdrant points.
Admin controls

Protected sync operations

POST /admin/sync/{provider} — run selected provider only
GET /admin/sync/status — all provider statuses + latest results
POST /admin/sync/{provider}/reindex/{storage_file_id} — force provider re-ingest
Failure isolation

Sync keeps useful work moving.

  • Invalid configuration: only that provider card stays disabled.
  • Auth/list/download failure: selected provider reports unavailable; trace stays safe.
  • Single-file ingestion failure: count failure, continue other files.
  • One provider failure cannot block another provider's manual sync.
Verification matrix

What must prove true

  • Provider adapterConfig, paging, recursion, MIME filtering, download, health per source.
  • IdentityProvider-qualified IDs isolate Drive, Dropbox, and future records.
  • Shared pipelineEvery downloaded file reaches extraction, description, embeddings, Qdrant.
  • OperationsEach provider has isolated manual control, status, traces, and safe disabled response.
